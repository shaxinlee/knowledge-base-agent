## 0. 文档定位

本文档是 `SDD.v0.1.md` 的前端分层补充规范，用于定义 v0.1 中 to C 用户端页面、to B 管理后台页面、登录入口、权限可见性和验收边界。

`SDD.v0.1.md` 仍是产品定位、架构边界、数据库设计、后端接口、RAG 链路、部署方式和 MVP 验收标准的事实来源。本文不得覆盖或放宽主 SDD 中关于单知识库问答、引用溯源、拒答、trace、feedback、Admin/User 权限边界和 v0.1 非目标的要求。

本文只约束以下前端范围：

- 前端入口选择页。
- to C 用户端问答页面。
- to C 用户端只读知识库页面。
- to B 管理后台入口保留。
- 登录后的角色跳转。
- 前端路由守卫和导航可见性。
- 前端中文文案与原型视觉参考边界。

本文明确不变更当前 SaaS 问答算法。实现时必须继续复用当前 conversation SSE、混合检索、rerank、LLM 回答、citation、trace 和 feedback 链路，不允许新增前端本地问答算法或第二套问答服务。

## 1. 背景与目标

当前 Web 页面同时承载问答和管理能力，整体更接近 SaaS 管理后台体验。本次前端分层将现有 SaaS 页面定位为 to B 管理后台，并新增或改造用户专用的 to C 问答体验。

目标如下：

1. 前端首页提供“用户页面”和“管理员页面”两个入口。
2. 普通用户面向“查看已有知识并问答”，点击用户页面前必须从下拉菜单选择一个已注册普通用户，不需要输入密码。
3. 管理员面向“维护知识库、文件、用户、审计和助手配置”，必须使用账号密码登录。
4. 用户端页面参考用户提供的原型风格，但正式展示文案必须使用中文。
5. 用户端问答继续使用当前 SaaS 问答算法和接口，不重写 RAG，不新增模拟回答。
6. 管理端现有功能、路径和权限边界保持不变。

本次分层后的产品语义：

- to C 用户端：用于消费已有知识、选择知识库、查看文件、提问、阅读引用和提交反馈。
- to B 管理后台：用于 Admin 创建和维护知识库、上传和解析文件、管理用户、查看审计日志和配置助手。

## 2. 角色与页面边界

### 2.1 `user`

普通用户允许：

- 通过首页“用户页面”入口选择已注册普通用户后进入系统。
- 进入 `/chat`。
- 进入 `/knowledge`。
- 进入 `/profile` 只读查看个人资料。
- 查看 active 知识库。
- 查看 active 知识库中包含的文件。
- 基于单个知识库提问。
- 查看回答引用。
- 查看引用中的文件名、source_locator 和原文片段。
- 查看图片引用预览。
- 提交 helpful / unhelpful 反馈。
- 查看、打开和删除自己的会话。

普通用户禁止：

- 创建知识库。
- 编辑知识库。
- 删除知识库。
- 上传文件。
- 重试解析文件。
- 删除文件。
- 进入 Chunk 调试页面。
- 进入用户管理页面。
- 进入审计日志页面。
- 访问管理后台专用入口。
- 使用跨知识库查询。
- 修改、删除或写回用户文件。

### 2.2 `admin`

管理员保留现有 SaaS 管理后台能力，允许访问：

- `/knowledge-bases`
- `/files`
- `/chunks`
- `/users`
- `/audit-logs`
- `/profile`

管理员继续负责：

- 创建、编辑、删除知识库。
- 上传文件。
- 查看文件状态。
- 重试解析。
- 删除文件。
- 查看 Chunk 调试信息。
- 创建、更新、禁用、启用用户。
- 重置用户密码。
- 查看审计日志。
- 配置助手资料。

管理员也可以访问 `/chat` 和 `/knowledge`，但管理功能仍应通过管理后台路径承载。

### 2.3 未登录用户

未登录用户只能访问入口选择页 `/` 和管理员登录页 `/login`。

未登录用户访问受保护页面时，前端必须跳转到 `/login`。后端仍必须通过 JWT 鉴权保护对应 API。

### 2.4 入口选择

前端根路径 `/` 是入口选择页，提供两个选项：

- 用户页面：先展示可进入用户下拉菜单，菜单项来自 Admin 用户管理中已注册且启用的普通用户；选择用户后调用普通用户免密会话接口，获取该 `user` 角色 token，并进入 `/chat`。
- 管理员页面：点击后进入 `/login`，管理员使用账号密码登录。

用户页面的免密会话只允许使用普通 `user` 角色账号，不得授予 admin 权限；admin 或已禁用账号不得出现在用户入口下拉菜单中。

## 3. 路由与导航规范

本次改造保留现有路径策略，不将管理后台整体迁移到 `/admin` 前缀。

路由定义如下：

| 路径 | 定位 | 允许角色 | 说明 |
| --- | --- | --- | --- |
| `/` | 入口选择页 | 未登录、user、admin | 选择用户页面或管理员页面 |
| `/login` | 管理员登录页 | 未登录、admin | 管理员账号密码登录 |
| `/chat` | to C 用户问答首页 | user、admin | 使用当前 SaaS 问答接口和算法 |
| `/knowledge` | to C 只读知识库页面 | user、admin | 展示 active 知识库卡片和文件列表 |
| `/profile` | 个人资料页面 | user、admin | user 只读资料；admin 额外显示助手配置 |
| `/knowledge-bases` | to B 知识库管理页 | admin | 创建、编辑、删除知识库 |
| `/files` | to B 文件管理页 | admin | 上传、状态、重试解析、删除文件 |
| `/chunks` | to B Chunk 调试页 | admin | 查看 Chunk 调试信息 |
| `/users` | to B 用户管理页 | admin | 管理用户和密码 |
| `/audit-logs` | to B 审计日志页 | admin | 查看高危操作审计 |
| `/forbidden` | 无权限提示页 | user、admin | 普通用户访问 admin 页面时跳转 |

普通用户导航只显示：

- 对话问答
- 知识库
- 个人资料
- 退出登录

管理员导航保留当前管理后台菜单：

- 对话问答
- 知识库管理
- 文件管理
- Chunk 调试
- 用户管理
- 审计日志
- 个人资料
- 退出登录

普通用户不得在导航、按钮、空状态或快捷入口中看到管理操作入口。管理员原有管理入口不得因用户端分层而丢失。

## 4. 登录与跳转规范

入口选择页要求：

- 点击“用户页面”前先调用 `GET /auth/consumer-users` 获取可进入普通用户列表；选择用户后调用 `POST /auth/consumer-session` 创建该普通用户会话，然后进入 `/chat`。
- 点击“管理员页面”时进入 `/login`，并清理当前普通用户会话，避免用户 token 自动跳转。

管理员登录继续使用现有 `/auth/login` API。

token 保存、刷新、退出继续使用现有前端 API 封装。退出登录后必须清理 access token 和 refresh token，并跳转回 `/login`。

管理员登录成功后按角色跳转：

- `admin` 默认进入 `/knowledge-bases`，或进入登录前被拦截的目标地址。

路由守卫要求：

1. 未登录访问受保护页面时跳转 `/login`。
2. 普通用户访问 admin 页面时跳转 `/forbidden`。
3. 已登录用户访问 `/login` 时，普通用户回到 `/chat`，管理员回到 `/knowledge-bases`。
4. 前端路由守卫只负责入口和可见性控制，后端 RBAC 仍是最终权限边界。

## 5. to C 问答页规范

`/chat` 是 to C 用户问答首页，页面必须使用当前 SaaS 问答算法和接口。

必须继续复用以下现有能力：

- active 知识库选择。
- 会话列表。
- 新建对话。
- 打开历史会话。
- 删除自己的会话。
- SSE 流式回答。
- 引用编号。
- 文件名。
- source_locator。
- 原文片段。
- 图片引用预览。
- helpful / unhelpful 反馈。
- 会话、消息、引用、trace 和 feedback 保存。
- 证据不足时拒答。

必须移除或隐藏普通用户创建知识库入口，包括：

- Chat 页面中的创建知识库按钮。
- “暂无可用知识库”状态下的创建入口。
- 任何通过用户端导航触达知识库新增、编辑、删除的入口。

无 active 知识库时，用户端显示中文提示：

```text
暂无可用知识库，请联系管理员维护知识库。
```

禁止行为：

- 不允许前端模拟回答。
- 不允许新增本地问答算法。
- 不允许绕过当前 SaaS conversation SSE 接口。
- 不允许跨知识库查询。
- 不允许用户在问答页创建、编辑或删除知识库。
- 不允许用户在问答页上传、删除或重新解析文件。

页面视觉应参考原型的轻量问答形态：左侧用户导航和历史会话，中间问答流，底部输入框，右侧引用或证据展示。但视觉调整不得改变问答数据流和权限边界。

## 6. to C 只读知识库页规范

新增用户端只读知识库页面，路径为 `/knowledge`。

页面展示 active 知识库卡片，字段包括：

- 名称
- 描述
- 文件数
- Chunk 数
- 更新时间
- 进入问答按钮

点击知识库卡片后，在同页显示该知识库包含的文件列表。文件列表字段包括：

- 文件名
- 类型
- 大小
- 文件状态
- 更新时间

文件列表使用现有接口：

```text
GET /knowledge-bases/{knowledge_base_id}/files
```

该页面不得显示以下管理操作：

- 上传
- 创建知识库
- 编辑知识库
- 删除知识库
- 重新解析
- 强制上传
- 删除文件
- Chunk 调试入口
- 解析任务详情
- 错误日志调试信息

空状态要求：

- 无 active 知识库：显示“暂无可用知识库，请联系管理员维护知识库。”
- 当前知识库无文件：显示“当前知识库暂无文件。”
- 接口错误：显示中文错误提示，并允许用户刷新。

## 7. 视觉与文案规范

用户端视觉参考原型的轻量 to C 风格：

- 浅色背景。
- 左侧轻量导航。
- 蓝紫主色。
- 问答内容居中。
- 底部输入框。
- 卡片式引用/证据展示。

正式文案必须全部使用中文。允许保留产品标识中的 `KB Agent`，也可使用 `知识库 Agent 助手` 等当前系统品牌表达。

不得引入原型中的以下范围外概念：

- 英文占位文案。
- 社区。
- 公开知识库。
- Premium。
- Billing。
- Trash。
- Help。
- 语音输入。
- 公开收藏。
- 支付、计费或套餐。

管理端可保持现有 SaaS 管理后台风格，但普通用户端不得暴露管理后台语义或按钮。

## 8. 非目标

本次前端分层明确不做：

1. 不改后端 RAG 算法。
2. 不改 embedding 链路。
3. 不改 BM25 / OpenSearch / PostgreSQL fallback 链路。
4. 不改 reranker 链路。
5. 不改 LLM 生成链路。
6. 不改 trace 保存链路。
7. 不改 feedback 保存链路。
8. 不新增跨知识库查询。
9. 不新增公开注册。
10. 不新增用户增删改知识库能力。
11. 不新增用户上传文件能力。
12. 不新增文档级权限。
13. 不新增计费。
14. 不新增公开广场。
15. 不新增社区知识库。
16. 不新增移动端 App。

## 9. 验收标准

本补充 SDD 的验收标准如下：

1. 普通用户登录后只看到用户端导航。
2. 前端根路径展示用户页面和管理员页面两个入口。
3. 用户选择已注册普通用户后无需输入密码即可进入 `/chat`。
4. 管理员点击管理员页面后必须通过账号密码登录。
5. 管理员登录后仍能使用原管理后台。
6. `/chat` 使用当前 SaaS conversation SSE 问答链路。
7. `/chat` 不出现普通用户创建知识库入口。
8. `/chat` 继续展示引用编号、文件名、source_locator、原文片段和反馈按钮。
9. `/knowledge` 可只读展示 active 知识库卡片。
10. `/knowledge` 可只读展示选中知识库中的文件。
11. 普通用户不能通过前端入口进行知识库增删改。
12. 普通用户不能通过前端入口进行文件上传、重试解析或删除。
13. 普通用户直接访问 admin 页面会被拦截到 `/forbidden`。
14. 管理端知识库、文件、用户、审计和助手配置功能不回退。
15. 用户端主要文案为中文，不出现原型英文占位或范围外商业化入口。
